# 同步服务部署说明

> 适用项目：`activity-worklog`（`server/` 目录）
> 服务默认只监听 `127.0.0.1:8787`，本机使用无需任何额外配置；跨机器同步需要按本文配置隧道或反向代理。

## 一、本机运行

```bash
cd server
cargo run
```

启动后控制台会输出：

- 服务地址（默认 `http://127.0.0.1:8787`）；
- 访问 Token，同时保存在数据目录的 `server-token.txt` 中。

数据目录：

| 系统 | 路径 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\activity-worklog-server\` |
| macOS | `~/Library/Application Support/activity-worklog-server/` |
| Linux | `~/.local/share/activity-worklog-server/` |

客户端「数据同步」页填写的 Token 必须与该文件一致。

## 二、让别的机器能访问

服务**不内置 HTTPS**，也没有用户体系，只有一个共享 Token，因此不要直接把裸端口暴露到公网。两种推荐方式：

### 方式 A：SSH 隧道（适合自己两台机器，最省事）

在「客户端机器」上建立到「服务端机器」的隧道：

```bash
ssh -N -L 8787:127.0.0.1:8787 用户名@服务端机器地址
```

然后客户端同步地址填 `http://127.0.0.1:8787`。流量全程走 SSH 加密，服务端依旧只监听本机，不需要改任何配置。

### 方式 B：反向代理 + HTTPS（适合长期在线的服务器）

先让服务监听本机地址保持不变（默认即可），再用 Nginx/Caddy 终止 TLS。Nginx 示例：

```nginx
server {
    listen 443 ssl;
    server_name worklog.example.com;

    ssl_certificate     /etc/letsencrypt/live/worklog.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/worklog.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
    }
}
```

客户端同步地址填 `https://worklog.example.com`。证书可用 Let's Encrypt 免费签发。

### 可选：直接监听所有网卡

如果前面已有网关或仅在可信内网使用，可通过环境变量修改监听地址：

```bash
# Linux / macOS
WORKBLOG_BIND=0.0.0.0:8787 cargo run
```

```powershell
# Windows PowerShell
$env:WORKBLOG_BIND = "0.0.0.0:8787"
cargo run
```

监听非回环地址时服务会打印安全警告。此模式下 HTTP 明文传输 Token，仅限可信内网。

## 三、接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 连通性检查 |
| POST | `/api/sync/records` | 推送日汇总（按 `device_id + date` 幂等） |
| GET | `/api/sync/records?days=N` | 拉取日汇总 |
| POST | `/api/sync/segments` | 推送时段明细 |
| GET | `/api/sync/segments?days=N` | 拉取时段明细 |
| POST | `/api/sync/delete` | 删除本设备指定日期 |
| GET | `/api/reports/daily` `/weekly` `/monthly` | 报表接口 |
| GET | `/` | 内置报表看板（页面内输入 Token） |

## 四、多设备语义（重要）

- 服务端按 `(device_id, date)` 存储，两台机器同一天各存各的，不再互相覆盖。
- 报表与「恢复历史」按**当天活跃时长最多的那台设备**取一条，避免重复相加。
- 删除只删本设备的行，不会误删另一台机器的数据。
- 客户端恢复时只补本地缺失的日期/时段，本地已手工编辑过的内容不会被覆盖。

## 五、备份

服务端数据为数据目录下的 `server.sqlite3`。迁移或升级前，先停服务并复制该文件；SQLite 文件复制即得到一致备份（如服务正在写入，建议用 `sqlite3 server.sqlite3 ".backup ..."` 做热备）。
