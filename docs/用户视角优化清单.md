> 日期：2026-11-06（第一轮 + 同日第二轮补齐）
> 范围：`E:\activity-worklog`（客户端 `src/`、`src-tauri/`，服务端 `server/`）
> 目的：不按代码结构、而按「用户真实会卡在哪里」重新审视一遍，把还能补齐的能力排成优先级。

本轮完成 5 项改动并已本地验证；剩余项按用户影响排序，附现状证据与建议做法，供后续排期。

## 一、本轮已落地

### 1. 补录任意一天（缺失日期不再是死角）

**用户场景**：忘开机、换了电脑、居家办公没启动客户端、请假后补卡——这些日子里列表里**根本没有这一行**，原来的「编辑时段」只能改已有记录，用户无路可走，只能去导 JSON 手改再导入。

**改动**
- 历史面板右上新增「补录一天」，打开补录面板：选日期 → 加/删工作或离开时段 → 保存。
- 默认日期直接落到「最近一个没有记录的工作日」，而不是今天（今天通常已有记录，会被挡住，白点一次）。
- 保存前校验：
  - 不允许未来日期；
  - 至少一个时段；
  - 起止时间不能倒置；
  - **时段不能重叠**（见第 2 项）；
  - 该日若已有段落，提示「请在历史行内编辑时段」，避免整段被覆盖。

**实现位置**：`src/main.tsx`（`openBackfill` / `saveBackfill` / 补录面板 JSX）、`src/styles.css`（`.backfillPanel` 等）。

### 2. 时段重叠校验（前后端双保险）

**用户场景**：手工补录时很容易把 09:30–12:00 和 11:50–18:30 叠在一起。`segment_stats` 是按秒累加的，重叠部分会被**算两次**，当天的活跃时长直接虚高，用户看着 12 小时的数字却不知道为什么。

**改动**
- 前端：`segmentOverlapError()` 统一校验倒置与重叠，行内编辑与补录都走它。
- 后端：`db.rs::replace_day_segments` 在落库前对时段排序后检查相邻区间，重叠直接拒绝并返回「时段之间存在重叠，请调整后再保存」，避免绕过前端写入坏数据。

### 3. 月度考勤 CSV（给 HR / 自己核对，不用再写公式）

**用户场景**：原来只有「导出 CSV（全部记录）」，列是日期/开始/结束/活跃/空闲。要交给 HR 或核对考勤，还得自己在 Excel 里补星期、算迟到、算早退、加合计。

**改动**
- 新增「导出当月考勤」入口（每日记录页图标 + 数据分析页按钮）。
- 按当前筛选月份出表；未筛选时取最近一个月。
- 列：日期、星期、上班、下班、活跃时长(小时)、活跃(分钟)、迟到(分钟)、早退(分钟)、加班(分钟)、备注，末行「合计」。
- 口径：周末不计迟到/早退，但**加班照常统计**；无活动的日子标注「无活动记录」；迟到/早退/加班 ≥30 分钟在备注里点名。
- 文件带 UTF-8 BOM，Excel 直接打开中文不乱码。

**验证**：用真实源码抽出该函数跑了 3 组样本（工作日迟到早退、周末加班、空白日），输出：

```text
日期,星期,上班时间,下班时间,活跃时长(小时),活跃(分钟),迟到(分钟),早退(分钟),加班(分钟),备注
2026-11-03,周二,09:45,18:10,7.17,430,15,20,0,
2026-11-07,周六,10:00,21:00,4.00,240,0,0,150,周末；加班
2026-11-09,周一,,,0.00,0,0,0,0,无活动记录

合计（2026-11）,3 天,,,11.17,670,15,20,150,
```

### 4. 从服务器恢复历史（换机/重装的兜底）

**用户场景**：此前同步只有 push。换电脑、重装系统、误点「清除全部记录」之后，服务器上明明有数据，客户端却只能靠手动 JSON 导入，且 JSON 得自己提前导出过。

**改动**
- 服务端 `GET /api/sync/records?days=N`：与推送共用同一路径，返回近 N 天日汇总（`server/src/main.rs::pull_records`）。
- 客户端 `pull_from_server`：读取配置 → 拉取 → **只插入本地缺失的日期**，不覆盖本地已有记录（本地可能已手工编辑过），补回的记录直接标记 `synced`，不会又被推回服务器形成回环。
- 数据同步页新增「从服务器恢复」，两步点击确认（第一次点击只提示，第二次才执行），避免误触。
- 恢复范围默认近 365 天，与服务器保留口径一致。

**边界（要在产品文案里讲清楚）**：同步链路只承载**日汇总**，不含时段明细。恢复后能看每天的开始/结束/活跃/空闲，但「编辑时段」需要本地原本就有该日的段落；需要完整明细请用 JSON 导出/导入。

### 5. 数据目录可见、可打开

**用户场景**：想手动备份或迁移，只知道「数据在本地 SQLite」，但不知道文件在哪；macOS 用户连 `~/Library/Application Support/...` 都找不到。

**改动**
- 新增 `db_path` / `open_data_dir` 两个命令（`src-tauri/src/main.rs`），设置页「数据备份与迁移」显示数据库绝对路径，并提供「打开数据目录」按钮（Windows 用资源管理器并带 `CREATE_NO_WINDOW`，macOS 用 `open`，Linux 用 `xdg-open`）。

## 一·续、第二轮补齐（同日，用户要求「优化完善好」之后）

第一轮列出的缺口里，有 6 项属于「用户天天会遇到、而且不需要外部条件就能做」，本轮直接做实。

### 6. 工作日 / 法定节假日 / 调休补班（报表口径不再固定按周一至周五）

**用户场景**：10 月一放长假，达成率立刻掉一半；春节、国庆前后公司调休上班的周六又永远算不进「工作日达成」。用户明明按公司日历上班，报表却判定他缺勤。

**改动**
- 设置页新增「工作日与节假日」面板：每周工作日多选（默认周一至周五）＋ 法定节假日日期列表 ＋ 调休补班日期列表。
- 判定顺序：**调休补班 > 法定节假日 > 每周工作日**，统一收敛到 `isWorkdayKey()` 一个函数。
- 报表里所有「工作日」口径（星期分布、平均上下班、达成率、本周/上周环比、本期早退天数）都改走它，不再各自用 `getDay()` 硬编码。
- 考勤 CSV 同步改为：节假日不记迟到早退、补班日按工作日算，备注分别标注「节假日」「非工作日」「调休补班」。
- 后端持久化：`AppSettings` 新增 `workdays` / `holidays` / `makeup_days`（带 `serde(default)`，旧配置自动补默认值，不会读不出来）。

**验证**：抽源码函数跑样本（周五设为节假日、周六设为补班）：

```text
日期,星期,上班时间,下班时间,活跃时长(小时),活跃(分钟),迟到(分钟),早退(分钟),加班(分钟),备注
2026-11-06,周五,09:20,17:00,6.67,400,0,0,0,节假日
2026-11-07,周六,09:40,19:30,7.00,420,10,0,60,调休补班；加班
```

节假日行迟到/早退归 0、补班行按 09:30 正常判迟到 10 分钟，符合预期。

### 7. 日历热图（最近三个月）

**用户场景**：想知道「这个月哪天断档了」「上周是不是连续加班」，原来只能在列表里一行行翻。

**改动**：数据分析页新增「日历热图」，最近三个月逐日格子按当天活跃时长分 5 档着色，休息日打虚线边框（用第 6 项的工作日历判断），悬停显示「日期 · 工作日/休息日 · 小时数」。随导出周报图片一起进入报告版面。

### 8. 首次引导加「应用锁」步骤

**用户场景**：应用锁藏在设置页深处，新用户跑完三步引导就进主界面，往往事后才发现有这个功能——而这恰恰是这类记录工具最该先开的开关。

**改动**：引导流程从 3 步变 4 步（隐私说明 → 数据同步 → 开机自启 → 应用锁），可直接设密码，也可「暂时跳过，直接完成」；设置成功后当场显示一次性恢复码，并同步主界面登录态，不用重启。

### 9. 一键下载并安装更新（不再跳 GitHub 手动装）

**用户场景**：检查到新版本后只能「前往下载」，用户要自己下安装包、手动替换，多数人就此放弃更新，长期停在老版本。

**改动**
- 新增 Rust 命令 `install_update`：走 `tauri-plugin-updater` 的 `download_and_install()`（下载 + 校验签名），完成后 macOS/Linux 自动重启，Windows 由安装器接管退出。
- 「关于」面板在发现新版本时新增「一键下载并安装」按钮，带下载中状态与失败原因提示，原下载链接保留作兜底。
- `tauri.conf.json` 补上 `bundle.createUpdaterArtifacts: true`（此前缺失，等于**从来没有产出过** `.sig` / 更新包），并设置 Windows `installMode: "passive"`（小窗口进度条，无需交互）。
- `release.yml` 矩阵加入 `windows-latest`：只发 macOS 包时，Windows 端根本拿不到对应平台的更新包，一键安装会一直失败。

> 注意：CI 需要仓库 Secrets 里已配置 `TAURI_SIGNING_PRIVATE_KEY`；若未配置，开启 `createUpdaterArtifacts` 后构建会直接报签名错误，而不是静默产出不可用的包。

### 10. 删除记录同步到服务器

**用户场景**：本地删掉误记的一天，服务器报表和云端看板里仍在，下次「从服务器恢复」还会把它拉回来——删了等于没删。

**改动**
- 服务端新增 `POST /api/sync/delete`（`delete_records`），按日期删除，返回实际删除的日期。
- 客户端 `HttpSyncClient::delete_records()`，`delete_day` 在本地删除成功后异步尽力同步；失败只写日志，不影响本地删除结果。

### 11. Linux 离开检测不再恒为 0

**改动**：Linux 分支改为调用 `xprintidle`（X11）读取系统空闲毫秒；未安装该工具或 Wayland 会话（无 `DISPLAY`）时返回 0，等价于「检测不到离开」，而不是假装一直在工作。行为与 Windows/macOS 对齐，Wayland 属于已知降级，需要时再补。

## 二、仍然值得做（按用户影响排序）

| 优先级 | 缺口 | 用户实际感受 | 现有证据 | 建议做法 |
| --- | --- | --- | --- | --- |
| P1 | **多设备互相覆盖（服务端按 date 做全局主键）** | 公司电脑和家里电脑同一天都有记录时，后推送的把先推送的覆盖掉，用户看到的「今日 8 小时」可能来自另一台机器 | `server/src/main.rs` 建表 `date text primary key`，`on conflict(date) do update` | 主键改 `(device_id, date)`，报表按设备或按「当天取最大活跃」聚合；需要一次数据迁移（本轮未动，避免静默改线上表结构） |
| P2 | **时段明细不同步** | 换机后只有日汇总，改不了历史某天的上下班时间，只能等本地重新记录 | `sync.rs` 的 `SyncPayload` 只含 `DailyRecord` | 复用 JSON 导入的 segments 结构，按天增量上传，注意体积与服务端表结构 |
| P2 | **数据库明文** | 应用锁只挡界面；拿到 `worklog.sqlite3` 就能直接读全部作息 | `rusqlite` 未启用 SQLCipher | 接 `rusqlite` 的 `bundled-sqlcipher` feature，密钥由应用锁密码派生；注意备份/恢复要带迁移提示 |
| P3 | **更新检查无失败原因分层** | 网络失败、签名失败和「仓库没有 Release」在界面上都只是「检查失败」，用户不知道要不要管 | `check_update` 把所有错误塞进 `status: "error"` + `notes` | 区分网络 / 签名 / 端点无产物，给出可操作的下一步（一键安装已能点，剩余是文案分层） |
| P3 | **日志不落盘** | 出现采集异常时只能看设置页最近 60 条，重启就没了，报障说不清 | 内存环形日志 | 写入 `data_dir/logs/app.log`（按天滚动、脱敏），设置页加「导出诊断包」 |

## 四、给用户的一句话结论

本轮把「忘记录的那一天没法补」「考勤没法直接交」「换机后云端数据拿不回来」「找不到数据库文件」这四个最具体的卡点补上了；第二轮继续把「节假日算错考勤」「更新要自己装」「删了云端还在」「Linux 不判离开」补齐。
下一步最值得做的是**多设备不再互相覆盖**：这一项不解决，用户量一上来就会持续收到「为什么我的数据变少了」这类反馈；它需要一次服务端主键迁移，建议单独排期、先备份再改。
