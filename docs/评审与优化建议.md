## 二、正确性：会算错或丢数据

### C1 恢复备份会覆盖恢复结果（P0）

`restore_db`（`main.rs:240`）在 mac 上校验并替换数据库，但没有通知采集循环丢弃内存缓冲。`spawn_activity_loop` 里的 `segments` 仍是恢复前的当天段落，下一个 15 秒 tick 会执行 `record_activity` → `persist_day_segments`，把当天段落整表删掉重写，等于把备份里"今天"的记录改回旧值。

**建议**：`restore_db` 成功后 `state.resetting.store(true, ...)`（与 `delete_day` 同样的处理），并让循环在 `resetting` 时重新 `load_segments_for_today()`，而不是只 `clear()`。

### C2 同步确认协议两侧不一致（P0）

- 服务端 `sync_records` 返回 `{"accepted": 12}`（计数）。
- 客户端 `sync.rs:62` 只认 `accepted` 为**字符串数组**，`as_array()` 返回 `None` → `unwrap_or(sent)` → 本次发送的全部日期都被 `mark_synced`。

也就是说：服务端因为日期格式非法跳过某天时，客户端的这条记录仍然被标记为"已同步"，之后永不重推——服务端永久缺这一天，本地却显示已同步。

**建议**：服务端改成返回 `{"accepted": ["2026-11-01", ...]}`，客户端去掉"没有该字段即全部成功"的兜底（只在 2xx 且显式确认时标记）；两边加一条协议契约测试。

### C3 每个 tick 都把当天置为 pending（P0）

`record_activity` 的 upsert 无条件 `sync_status = 'pending'`（`db.rs:201`），`close_open_segments` 同样（`db.rs:307`）。只要采集在跑，当天记录每 15 秒就"变脏"一次，同步间隔一到就整条重推。

**建议**：只在 `active_minutes / idle_minutes / first_activity_at / last_activity_at` 真的变化时才置 pending（比较后再 update），或引入 `revision` 计数器做增量同步。

### C4 366 天硬上限（P0）

`list_daily_records` 写死 `limit 366`（`db.rs:348`），而 CSV 导出（`db.rs:423`）就是基于它。第二年之后：历史列表看不到更早数据、CSV 少一年、分析页"全部"其实只有一年。

**建议**：列表改分页（`limit/offset` 或按月份查），导出走全量查询；UI 上明示数据范围。

### C5 桌面端也会展示演示数据（P0）

- `main.tsx:422-424`：`list_segments` 失败时 `.catch(() => setSegments(fallbackSegments))`，没有判断 `inTauri`。锁屏、IPC 报错、数据库异常都会让"今日时间线"显示编造的段落。
- `main.tsx:2240`：`const data = records.length ? records : fallbackRecords;` —— 桌面端新装、零记录时，分析页会显示 28 天假数据。

**建议**：演示数据只在 `!inTauri` 时启用；桌面端失败就显示空态 + 重试。

### C6 状态行 15 秒被重置（P1）

`refresh()` 末尾 `setStatus("后台监听已开启")`（`main.tsx:316`），而 `records-updated` 每 15 秒触发一次 refresh。于是"已备份：C:\...\x.sqlite3""今日小结：..."这类提示最多活 15 秒。`saveFeedback` 已经是一条独立通道，状态行不该兼做通知。

**建议**：状态行只表示"采集/暂停/权限"这类持久状态；操作结果统一走 toast（`saveFeedback` 复用）。

### C7 边打字边落库（P1）

`sync_url`、`sync_token` 的 `onChange` 直接 `updateSettings(...)`（`main.tsx:1216`、`1225`）。每次按键都会：写 settings JSON → 调用 `autostart.enable()/disable()`（`main.rs:124-136`）。窗口尺寸变化也走同一条路径（`silent=true` 但照样 invoke）。

**建议**：
1. 文本类字段本地 state + 失焦/防抖 400 ms 后再保存；
2. `save_settings` 里 autostart 与写库解耦，自启失败只记日志，不要让整次保存失败；
3. 加一个 `save_window_size` 独立命令，避免改尺寸触发自启逻辑。

### C8 应用锁的安全边界（P1）

- `get_settings`（`main.rs:114`）没有 `ensure_unlocked`，而 `AppSettings` 含 `password_hash` / `recovery_hash`（`settings.rs`），会原样序列化给前端。前端 TS 类型没声明这两个字段，但数据确实到了 webview。
- `tauri.conf.json` 里 `"csp": null`：没有 CSP，一旦有注入点（导出、更新说明等渲染外部内容）就能直接调 `invoke`。
- `unlock` 的冷却只存在内存（`cooldown_until: Mutex<Option<Instant>>`），重启应用即清零；`set_password`、`disable_lock` 完全不限次。

**建议**：`get_settings` 返回脱敏结构（`{...settings, password_hash: None}` 或不含锁字段的 DTO）；加 `has_password` 已有，够用。CSP 至少给到 `default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'`。所有校验密码的入口共用同一个失败计数器，并把冷却时间落库（重启也生效）。生产包里 `recovery_hash` 建议只在内存驻留。

### C9 路径与命令注入面（P2）

`export_report(filename, ext)`（`main.rs:603`）直接把前端传的 `filename` 拼进 `dir.join(...)`，`../../` 可写出目录外；`notify_macos` 用 osascript 拼接字符串（当前 message 是常量，暂时安全）。**建议**：`filename` 只保留 `[\w\u4e00-\u9fa5-]`、`ext` 白名单（png/pdf/csv），通知改用 `tauri-plugin-notification`。

### C10 时间与时区（P2，待真机验证）

段落里只存 `HH:MM:SS`（`activity_segments`），`parse_time_seconds` 解析失败返回 `0`（`db.rs:parse_time_seconds`）。跨时区、夏令时回拨、手工改系统时间时，`ended_at < started_at` 会被 `max(0)` 静默吃掉，`gap_break` 判断也会失效。

**建议**：段落改存 UTC 时间戳（或带偏移的 RFC3339），展示时再转本地；解析失败返回 `Result` 而不是 0；跨天/时区跳变写一条日志便于排查。

### C11 服务端数据模型（P1）

`synced_records` 用 `date` 做全局主键（`server/main.rs`），`device_id` 只是普通列。两台设备同一天都上报 → 后到的覆盖先到的。多用户/多设备场景直接冲突。

**建议**：主键改 `(device_id, date)`，并加 `revision`/`received_at` 做 last-write-wins 之外的冲突检测；报表按设备/用户聚合。

## 三、性能与稳定性

| 项 | 现状 | 建议 |
|---|---|---|
| 采集循环 | 每 15 秒：写库（删+重插当天全部段落）、全量 `list_daily_records()` 算托盘 tooltip、`emit("records-updated")` | tooltip 用内存 `segments` 算；只在数据变化时 emit；段落增量更新（`update ... where id=?`）而不是整表重写 |
| SQLite | 默认 journal（rollback），无 `busy_timeout`，单连接 + `Mutex` | `PRAGMA journal_mode=WAL; synchronous=NORMAL; busy_timeout=5000`；写操作集中到采集循环，读用第二个只读连接 |
| IPC 数据量 | `export_report` 传 `Array.from(Uint8Array)`，MB 级图片/PDF 会变成几十 MB 的 JSON 数组 | Tauri 2 直接传 `Uint8Array`/`ArrayBuffer`（`invoke` 支持），或写临时文件只传路径 |
| 前端刷新 | 每 15 秒 4 次 invoke（records + settings + sync_summary + segments） | 合成一个 `snapshot` 命令；或 records 用增量（返回 `updated_at` 之后的变动） |
| 同步重试 | 失败后等满一个 `sync_interval`（默认 15 分钟）才重试，无退避、无"下次重试时间" | 指数退避（1/2/5/15 分钟），失败状态写进 `sync_summary` 让界面可见 |
| 首屏包 | 主 chunk 578 KB（gzip 约 191 KB），其中 **jsPDF 约 350 KB 只在导出 PDF 时用到**；html2canvas/purify 已经是按需 chunk（说明这条路可行） | `main.tsx` 顶部的 `import { jsPDF } from "jspdf"` 改成导出函数内的 `await import("jspdf")`；`html-to-image` 同理 |
| 日志 | 只在内存保留 60 行，重启即失；后端错误大量 `let _ = ...` 吞掉 | `tauri-plugin-log` 落盘 + 轮转；关键失败路径（写库、同步、恢复、自启）至少 `log::warn!` |
| 退出 | 托盘退出 `app.exit(0)` 不 flush 当前段落，最后一段最多丢 15 秒 | 监听 `RunEvent::ExitRequested`，先 `close_open_segments` 再退出 |

## 四、体验与设计

### 4.1 信息架构

- 「设置」页承载 7 个 panel（常用设置、应用锁、作息、隐私、关于、备份、日志），滚动很长且权重相近。建议拆成 **常规 / 安全 / 数据 / 关于** 四个 tab，日志放到「数据」里做可折叠区域。
- 「每日记录」页首屏信息密度高（状态条 + 环形 + 4 个指标 + 时间线 + 历史表），但**环形占比和 4 个指标有重复语义**（活跃时长 vs 目标 vs 占比）。建议首屏只留"开始 / 结束 / 活跃 / 距目标"，把占比移进分析页。

### 4.2 具体的界面问题

| 位置 | 问题 | 建议 |
|---|---|---|

### 4.3 可达性与视觉

- `--text-faint`（#8a939c）在白底对比度实测 **3.12:1**，被用在时间线刻度（10.5px）和图表轴标签（12px）上，低于 WCAG AA 的 4.5:1；深色主题 3.96:1 同样偏低。正文 hint 用的是 `--text-dim`（5.93:1，合格）。建议把 faint 提到 #6f7a76 级别，或仅用于非文字元素。
- 图标按钮只有 `title`，没有 `aria-label`；历史行是 `role="button"` 里嵌了 `<button>`（ARIA 嵌套不合法），建议行改成 `<div>` + 独立的键盘可聚焦删除按钮。
- `prefers-reduced-motion` 和 `:focus-visible` 都已经做了，这点很好，可以继续保持。
- 窗口 `minWidth: 960`，而 CSS 里 720/520px 的断点永远命中不到（可删或降到 <960 才有意义）。
- `titleBarStyle: "Overlay"`：侧边栏已经用 `padding-top: 46px` 避让 macOS 红绿灯，这点处理对了。但全局没有 `data-tauri-drag-region`，可拖动区域只有系统标题栏那一条 28px；建议给侧边栏顶部空白区和顶栏加 `data-tauri-drag-region`，让用户能在内容区拖窗口。
- `skipTaskbar: true`（Windows）：任务栏和 Alt+Tab 都看不到，只剩托盘。建议加**全局快捷键**（如 `⌘/Ctrl+Shift+L`）唤出窗口，首次引导里告知。

## 六、产品功能缺口（按用户价值排序）

1. **记录时间可编辑（最高）**——现在只能整天删除。忘开机、换设备、临时离席都会让某天数据错，用户唯一的补救是"删掉一整天"。需要"补录开始/结束时间 + 手动加一段工作/离开"。
2. **数据保留期与自动清理**——`daily_work_records` 只增不减，366 天只是显示上限，库会一直长。
3. **多设备**——服务端主键冲突（C11）+ 设备标识用数据目录路径哈希（换用户/换路径就变），多机场景实际上不可用。建议客户端生成并持久化 UUID。
4. **工作日/节假日**——"工作日达成率""早退"把法定假日算成缺勤；建议支持导入/标记节假日与请假。
5. **全局快捷键 + 菜单栏实时时长**——隐藏入口的应用必须有"一眼看到 + 一键唤出"的路径，现在只有 tooltip。
6. **Windows 端补齐**——`restore_db` 文件选择器、系统通知（现在 `notify_macos` 在 Windows 上静默失败）、托盘菜单本地化。
7. **自动更新真正可用**——目前只做版本比对 + 跳转下载页，没有 `downloadAndInstall`；既然已经配了 `pubkey`，可以接上"下载并重启安装"。
8. **Web 后台**——现在是一张单页表格 + 共享 Token，没有登录、没有图表、Token 不持久化；如果要做团队报表，需要账号体系和 `(user, device, date)` 三级模型。
