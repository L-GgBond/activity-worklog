## 项目分析：Activity Worklog（/Applications/code/ere）

- 性质：Tauri 2 桌面端“隐私友好型工作时长记录工具”（React+TS 前端 / Rust 后端）。
- 启动方式：`npm run tauri:dev`（先起 Vite@1420，再编译并拉起原生窗口）。发布：`npm run tauri:build`（产物 dmg 在 `src-tauri/target/release/bundle/dmg/`）。
- 另含可选 `server/` 目录：独立 Axum(Rust) Web 后台，接收同步上报并返回日报/周报/月报，桌面端“数据同步”页默认指向 http://127.0.0.1:8787（`cargo run` 启动，非运行桌面端必需）。
- 活动检测：macOS 用 IOHIDSystem HIDIdleTime（读系统空闲时间，**无需辅助功能/输入监控权限**）；Windows 用 GetLastInputInfo。
- 环境已就绪：Node 22、Rust 1.97(Homebrew)、node_modules 已装、cargo target 已编译。已验证 `cargo check` 与 `npm run build` 均通过。
- 注意：窗口 `visible:false`，启动后需点菜单栏托盘图标“显示记录”才可见；首次启动有引导向导(onboarding)。
- **已构建桌面安装包**：`npm run tauri:build` 的 release 编译通过（~50s），但 Tauri 自带 `bundle_dmg.sh` 失败；改用 `hdiutil create -volname "Activity Worklog" -srcfolder <app> -format UDZO` 生成标准 DMG 成功。成品：`src-tauri/target/release/bundle/dmg/Activity Worklog_0.1.0_aarch64.dmg`（6.3M，校验 VALID，无 quarantine，本机可直接拖入应用程序运行）。已对 .app 重新 ad-hoc 深度签名。分发到其他机器需 Developer ID 签名+公证。
- **修复“桌面端没有界面”**：根因是 `tauri.conf.json` 窗口 `visible:false`（启动隐藏，仅留菜单栏托盘）。已改为 `visible:true` 并重新打包 DMG（release 编译 ~27s）。验证：直接运行二进制可正常存活、无崩溃；config 确认 `visible:true`。用户需在自身 GUI 会话中打开新 DMG 的 .app 才能看到窗口（agent 后台拉起的 GUI 不保证出现在用户屏幕）。
